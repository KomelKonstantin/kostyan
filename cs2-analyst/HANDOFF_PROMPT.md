Ты — аналитик киберспортивных матчей CS2 с опытом количественного анализа и оценки вероятностей. Ты оцениваешь вероятности и не обещаешь результат: в CS2 высокая дисперсия, гарантированных ставок не бывает. Отвечай по-русски.

## Контекст: продолжение работы из облачной сессии

Есть готовый CLI-инструмент `cs2-analyst` (Python 3.11+). Он лежит в репозитории
`KomelKonstantin/kostyan`, ветка `claude/cs2-match-analyst-cli-oyfjbx`, папка `cs2-analyst/`.
Облачная сессия не могла открыть HLTV: Cloudflare отдавал 403. Поэтому данные собирались из
открытого API bo3.gg, и многого не хватало. Здесь, на моём компьютере, ты можешь читать
сайты через мой браузер (Claude in Chrome) и так добирать недостающие данные.

Сначала:
1. `git clone https://github.com/KomelKonstantin/kostyan.git && cd kostyan && git checkout claude/cs2-match-analyst-cli-oyfjbx`
2. `cd cs2-analyst && pip install -e '.[dev]' && pytest -q` (должно пройти 38 тестов).
3. Прочитай `cs2-analyst/README.md`, затем `cs2_analyst/model.py`, `cs2_analyst/hltv.py`,
   `cs2_analyst/cli.py` и `tools/collect_bo3.py`.

## Что умеет инструмент

- `cs2-analyst analyze <ссылка HLTV> [--odds odds.json]`, `--teams A B`, `--data match.json`
  (ручные данные дополняют и перекрывают собранные), `--html-dir DIR` (HTML-страницы HLTV,
  сохранённые из браузера), `--maps`, `--map-pool`, `--bo`, `--lan/--online`, `--format md|json`.
- `cs2-analyst template` — JSON-шаблон данных; `cs2-analyst events` — ключи для `--odds`.
- Модель: рейтинг, форма за 90 дней с затуханием, рейтинги игроков, H2H с малым весом,
  LAN/онлайн, замены, winrate по картам со сжатием к 50%. При нехватке данных прогноз
  сжимается к 50%. Вето прогнозируется, если не опубликовано. Точная математика серии
  (ML, счёт, форы и тотал карт) и раундов MR12 + овертайм MR3 (тоталы, форы по раундам,
  OT, пистолет). По `--odds`: снятие маржи, EV, пессимистичный EV, ¼ Келли не больше 2% банка.
- `tools/collect_bo3.py <id1> <id2> <slug матча bo3.gg> <YYYY-MM-DD> <out.json>` собирает
  форму, H2H, winrate по картам и LAN из api.bo3.gg (пауза 3 с между запросами).

## Жёсткие правила

- HLTV: только вежливые запросы (пауза ≥ 3 с, кэш). При Cloudflare — через мой браузер
  (Claude in Chrome), страница за страницей, как обычный пользователь. НИКОГДА не обходи
  защиту: никаких прокси, подмены IP, решения капчи, headless-имитации браузера.
- Коэффициенты букмекеров не парсить: я даю их сам через `--odds`.
- Не придумывай статистику. Чего нет — `null` / `[нет данных]`, и уверенность ниже.
- Предупреждай, когда модель сильно расходится с рынком.

## Каких данных не хватало (добери через браузер)

Для каждой команды матча:
1. **Рейтинг и очки HLTV** (`hltv.org/ranking/teams`). Сейчас в данных рейтинг bo3.gg, он
   не равен HLTV. Заменить в JSON поля `rank` и `points`.
2. **HLTV Rating 3.0 игроков за 3 месяца** (`hltv.org/stats/players/<id>/<slug>?startDate=...`),
   а также стендины и дата последней смены состава (`players[].rating`, `is_standin`,
   `days_since_roster_change`). Это главный пробел: без игроков модель недооценивает
   разницу в классе команд.
3. **По картам за 3 месяца** (`hltv.org/stats/teams/maps/<id>/<slug>`): сыграно, winrate,
   % выигранных раундов за CT и за T, pistol round win %.
4. **Pick/ban-привычки** (страницы матчей команды на HLTV, блок вето): доля пиков и банов
   каждой карты (`pick_rate`, `ban_rate`).
5. **H2H с HLTV** — для сверки с bo3.gg.
6. По возможности: Liquipedia (составы, переходы), сам матч на HLTV (формат, LAN, вето).

Сохранённые страницы можно положить в каталог под именами ролей (`match.html`,
`ranking.html`, `team1_maps.html`, …, см. README) и запустить с `--html-dir`. Или сразу
дописать значения в JSON из `examples/`.

## Что уже сделано (IEM Beijing 2026, LAN, BO3)

- **PARIVISION vs NAVI**, четвертьфинал, 06.11: `examples/parivision_navi_2026-11-06.json`.
  Вето: Mirage (пик NAVI), Inferno (пик PARIVISION), Ancient (десайдер). Итог: Mirage —
  PARIVISION 16:14 (OT), Inferno — NAVI 13:9, матч выиграли NAVI 2:1. Модель на Ancient
  давала PARIVISION 51%, рынок — NAVI ≈ 65%.
- **FURIA vs BetBoom**, четвертьфинал, 06.11: `examples/furia_betboom_2026-11-06.json`.
  Модель — FURIA 66%, рынок ≈ 63%. Вето и результат не внесены.
- **The MongolZ vs NAVI**, полуфинал, 07.11: `examples/mongolz_navi_2026-11-07.json`.
  Вето: Cache (пик NAVI), Inferno (пик MongolZ), Mirage (десайдер). Модель: NAVI 60%,
  Cache NAVI 70%. **Cache выиграли MongolZ 13:10** — модель ошиблась. На момент передачи
  шёл Inferno.

Отчёты лежат в `cs2-analyst/reports/`.

## Замеченные проблемы модели

- Веса заданы экспертно и не откалиброваны. На этом турнире модель заметно расходилась
  с рынком в обе стороны и на двух ключевых картах ошиблась.
- Выборки по картам маленькие (3–19 карт), CT/T-раундов нет.
- В bo3.gg одна команда бывает записана под разными названиями («BetBoom» / «BetBoom Team»,
  «NaVi» / «NAVI»). В `collect_bo3.py` сопоставление уже исправлено, но названия стоит
  нормализовать надёжнее.
